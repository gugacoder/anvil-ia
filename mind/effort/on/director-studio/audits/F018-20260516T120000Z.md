# F018 — audit-veto

## Veto detalhado

### D4 — allowedDates formato divergente
Legado: `allowedDates` em `dd/mm/yyyy` (formato exibição). Studio: `string[]` em `YYYY-MM-DD`.
Consumidor que recebe `/data/disponiveis` do backend (formato legado) tem 100% das datas bloqueadas. Sem toast de rejeição equivalente.

**Fix sugerido**: aceitar ambos formatos no `disabledDays` (normalizar via `parseISO`/`parseDDMMYYYY` no adaptador) OU adicionar helper `allowedDatesFromLegacy(csvList)` em `date-csv.ts`.

### D5/D6/D9 — defaults computados ausentes
Legado: `useDefaultDate=true` no mount dispara `onChange` com `[hoje-1d, hoje]` (DateInterval) ou `[hoje 00:00, hoje 23:59]` (DateTimeInterval). UX spec exige `defaultValue: 'today' | 'last-7-days' | () => objeto` declarativo.

Studio implementação: sem prop `preset`. Sem auto-emit no mount em modo `defaultValue`. Botão "Hoje" no popover é interação manual, não default declarativo.

**Fix sugerido**: prop `preset?: 'today'|'yesterday'|'last-7-days'|'this-month'|'last-month'` que computa valor inicial no mount e emite `onChange`. Cobre D5/D6/D9 num só fix.

### D11 — customConfig.endDateInterval='startOfMonth'
Legado tem opção pra range default `[start-of-month, today]`. Studio não tem.

**Fix sugerido**: incluir preset `'this-month'` que mapeia pra `[startOfMonth(today), today]`.

### D12 — igualdade uniformizada
Legado: `DateInterval` permite `from==to`; `DateTimeInterval` rejeita. Studio: ambos permitem.

**Fix sugerido (baixa prioridade)**: prop opcional `equalityMode?: 'allow'|'reject'`, default `'allow'`. Para datetime-range, default `'reject'` se quiser paridade total. Ou aceitar divergência como nota.

### D13/D14 — FormFieldTimeRange ausente
Legado `TimePicker` é par `[De, Ate]` apesar do nome. Studio só tem `FormFieldTime` single. `Mode` em `date-csv.ts:11` não inclui `"time-range"`.

**Fix sugerido**: criar `FormFieldTimeRange` (mobile drawer / desktop popover) com dois TimeControls lado-a-lado, payload `{from: "HH:mm", to: "HH:mm"}`. Estender `Mode` pra incluir `"time-range"`. Adaptador `dateValueToCSV` emite `"HH:mm,HH:mm"`.

### D17 — fetch dinâmico allowedDates
Legado: `api="/data/disponiveis"` + `pageState` → POST no `onCalendarOpen`. Studio: só aceita `allowedDates: string[]` estático.

**Fix sugerido (opt 1)**: prop `allowedDatesEndpoint?: {url, body}` que dispara fetch no mount/open. Loading state visual durante request.
**Fix sugerido (opt 2)**: aceitar divergência mas registrar nota no manifest "fetch dinâmico delegado ao consumidor — passa array pronto via `allowedDates`".
