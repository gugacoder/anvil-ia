## Veto

### A16 ferida — `nomeEmpresa` não é a sentinela `"Processa"` do contrato

Contrato (`processa-auth-ldap-bridge.md` linha 159, A16):
> smith deve mapear principal do Studio como `{ id: 1, nome: <user-com-backslash>, codEmpresa: 1, nomeEmpresa: "Processa", grupos: <dados>, path: 'ldap-bridge' }`. **`Id=1, CodEmpresa=1` são sentinelas — não lookups reais**; preservar para compatibilidade legada.

Fonte legado (`processa-auth-ldap-bridge.md` linha 35, citando `AbstractBearerAuth.cs:100`):
> `DirectorIdentity(1, name, 1, "Processa")`: usuário LDAP sempre recebe `Id=1, CodEmpresa=1, NomeEmpresa="Processa"` (sentinela — o identity real do AD não é resolvido contra `acesso.TBusuario`, é fixo).

Diff em `workspace/director-studio/apps/api/src/routes/auth.ts:268-280` (linhas no diff aplicado):
```ts
const grupos = Array.isArray(envelope.dados)
  ? (envelope.dados as unknown[]).map((g) => String(g))
  : []
// Se algum grupo AD parecer indicar empresa, use; senão fallback 'LDAP'.
const nomeEmpresa = grupos.length > 0 ? grupos[0] : 'LDAP'
return {
  kind: 'ok',
  principal: {
    id: '1',
    nome: identity,
    codEmpresa: 1,
    nomeEmpresa,
    path: 'ldap-bridge',
    loginAt: new Date().toISOString(),
  },
}
```

Smith substituiu a sentinela fixa `"Processa"` (paridade legado) por uma heurística (`grupos[0]` ou fallback `'LDAP'`). Isso:

1. Quebra a paridade literal do `NomeEmpresa` sentinela.
2. Introduz semântica nova ("primeiro grupo AD é o nome da empresa") que **não está no legado** nem no contrato — `dados` é lista de grupos AD (CN/sAMAccountName de grupos), não nome de empresa.
3. Para fidelidade A16, `nomeEmpresa` deve ser literal `"Processa"` em **todos** os casos de sucesso do path `ldap-bridge`.

### Nota A16 (passa com ressalva)

O contrato A16 também menciona `grupos: <dados>` no principal mapeado. O `SessionPrincipal` mapeado por smith **não inclui `grupos`** — apenas `id, nome, codEmpresa, nomeEmpresa, path, loginAt`. O array de grupos é construído (`const grupos = ...`) e usado só para alimentar a heurística `nomeEmpresa`, não persiste no principal/sessão.

O contrato é ambíguo aqui: o legado armazena grupos em `identity.Grupos` (campo da `DirectorIdentity`), mas o `SessionPrincipal` do Studio pode ter shape diferente. Não há asserção dedicada explicitando "principal DEVE conter `grupos`". Reporto como nota de gap — não como veto independente — porque A16 só lista `grupos: <dados>` no shape exemplo, sem afirmar mandatoriedade discriminada (vs `id`, `codEmpresa` que estão marcados como "sentinelas — preservar"). Pode virar asserção própria em wave de descoberta.
