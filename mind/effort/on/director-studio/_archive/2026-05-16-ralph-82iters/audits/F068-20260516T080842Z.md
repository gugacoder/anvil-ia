# Audit veto: F068 — Temp password offline

Smith implementou `validateTempPassword` em `workspace/director-studio/apps/api/src/routes/auth.ts:127-157` e o case `'temp-password'` no `/login` em `workspace/director-studio/apps/api/src/routes/auth.ts:613-640`. Confrontei contra T1..T25 de `mind/atlas/concepts/legacy-contracts/processa-auth-temp-password.md`. Listo abaixo as asserções **feridas** com citação. As demais asserções (T1, T4, T13, T14, T18, T19, T20, T22, T23, T24, T25, mais T5/T8/T9 que passam por equivalência observável) ou passam ou estão fora de escopo do diff (T14/T19/T20/T22 são sobre geração, que smith não implementa, e T18 é sobre middleware externo).

## Vetos

### T2 — Camada base64 interna do salt ausente

**Contrato (`processa-auth-temp-password.md:108`)**: `Convert.ToBase64String(Encoding.ASCII.GetBytes(Convert.ToBase64String(Encoding.ASCII.GetBytes(K.Substring(r, 6))) + K.Substring(50, 7) + ...))` — salt é base64-encodado **antes** de concatenar com separator+timestamp. O plaintext interno tem **três pedaços**: `base64(salt) + separator + expiry`.

**Legado (`sources/engenharia--fabrica--dotnet--processa.sdk/Fontes/Processa.Sdk.Auth/TokenUtils.cs:140-141`)**: interpolação `$"{Convert.ToBase64String(saltByteArray)}{splitedStringKey}{...}"` — base64 do salt como primeiro pedaço.

**Smith (`workspace/director-studio/apps/api/src/routes/auth.ts:135-138`)**:
```
const idx = plaintext.indexOf(sep)
const salt = plaintext.slice(0, idx)
if (salt.length === 0 || !secret.includes(salt)) return false
```

Smith trata `passwordSplited[0]` como o salt cru de 6 chars, mas conforme T2 esse pedaço é a base64 do salt (8 chars). Falta o `Convert.FromBase64String(passwordSplited[0])` + `Encoding.ASCII.GetString` (legado `TokenUtils.cs:166-167`) que recupera os 6 chars ASCII originais antes do `Contains`.

### T3 — Round-trip com token gerado pelo legado falha

**Contrato (T3, `processa-auth-temp-password.md:109`)**: token recém-gerado por `GenerateTempPassword(3600)` valida `true` quando passado a `ValidateTempPassword`.

**Legado (`TokenUtils.cs:169`)**: `if (!Consts.SecretKey.Contains(saltString)) return false;` onde `saltString` são os **6 chars cru** decodificados de `passwordSplited[0]`.

**Smith (`workspace/director-studio/apps/api/src/routes/auth.ts:138`)**: `secret.includes(salt)` onde `salt` é a string base64 de 8 chars (não decodificada). Como `SecretKey = "aAGoWJTM…OYOHJxX…"` (118 chars ASCII alfanumérico puro) e a base64 de 6 bytes alfa-numéricos produz padrões com chars que praticamente nunca aparecem como substring contínua em SecretKey, `secret.includes(base64Salt)` retorna `false` em praticamente 100% dos tokens legítimos.

**Resultado**: round-trip canônico exercitado em `sources/.../Sandbox/Program.cs:759-760` (`var t = GenerateTempPassword(3600); var v = ValidateTempPassword(t);`) retorna `true` no legado e **`false` no Studio**. Token gerado pelo botão "passwordTemp" do ADM legado **não** autentica no Studio. Quebra de paridade absoluta. T21 (round-trip explícito) fere pelo mesmo motivo.

### T15 — Identity sentinela: case do `nome` divergente

**Contrato (`processa-auth-temp-password.md:96-99` + T15 `:121`)**: `DirectorIdentity(Id=1, Nome="processa", CodEmpresa=1, NomeEmpresa="Processa"){ Domain="Director" }`. **`Nome` é literal lowercase `"processa"`**.

**Legado (`sources/engenharia--fabrica--dotnet--processa.sdk/Fontes/Processa.Sdk.Auth/AbstractBearerAuth.cs:145`)**: `new DirectorIdentity(1, "processa", 1, "Processa") { Domain = "Director" }` — segundo argumento `"processa"` minúsculo.

**Smith (`workspace/director-studio/apps/api/src/routes/auth.ts:633`)**: `nome: 'PROCESSA'` (maiúsculo).

Divergência observável: qualquer consumidor que renderize `principal.nome` (UI, logs, headers Director-User, `/api/auth/me`) vê string diferente da legada. O `Domain="Director"` também não é propagado no `SessionPrincipal` smith (campo ausente do tipo) — registrado como nota, não veto independente, porque o tipo `SessionPrincipal` não tem o slot.

### T6 — Separator ausente: retorno `null` vs `false`

**Contrato (T6, `processa-auth-temp-password.md:112`)**: separator não encontrado → `null` (catch externo via `passwordSplited[1]` out-of-range).

**Legado (`TokenUtils.cs:164,172-176`)**: `Split` produz array de 1; acesso a `[1]` lança; catch retorna `null`.

**Smith (`workspace/director-studio/apps/api/src/routes/auth.ts:135-136`)**: `if (idx < 0) return false`.

Observavelmente equivalente via `?? false` do `AuthenticateTempPassword` legado, mas o tipo `bool?` do contrato é colapsado em `boolean` no smith — o tri-state é perdido. Inerte para o middleware atual, mas viola a asserção literal.

### T7 — Base64 externo malformado: retorno `null` vs `false`

**Contrato (T7, `processa-auth-temp-password.md:113`)**: `Convert.FromBase64String("not-base64!")` lança `FormatException` → catch → `null`.

**Legado (`TokenUtils.cs:163,172-176`)**: idem.

**Smith (`workspace/director-studio/apps/api/src/routes/auth.ts:129-133`)**: `Buffer.from(password, 'base64')` em Node.js **não lança** para strings inválidas — decodifica leniente, ignora chars fora do alfabeto, produz buffer parcial/vazio. O try/catch é morto. Caminho cai em `indexOf(sep) < 0` → `false`. Mesma divergência tri-state de T6.

### T10 — `passwordSplited[0]` não-base64: retorno `null` vs caminho inexistente

**Contrato (T10, `processa-auth-temp-password.md:116`)**: `Convert.FromBase64String(passwordSplited[0])` lança → catch → `null`.

**Legado (`TokenUtils.cs:166,172-176`)**: idem.

**Smith**: smith **não decodifica `passwordSplited[0]`** (vide T2/T3 acima). Não há caminho equivalente. Em vez de cair em `null`, smith faz `secret.includes(salt)` sobre a string ainda em base64 e retorna `false`. Asserção colapsada por consequência do veto T2.

### T11 — Timestamp inválido: retorno `null` vs `false`

**Contrato (T11, `processa-auth-temp-password.md:117`)**: `DateTime.Parse("abc")` lança → catch → `null`.

**Legado (`TokenUtils.cs:170,172-176`)**: idem.

**Smith (`workspace/director-studio/apps/api/src/routes/auth.ts:140-141`)**: `ts.match(/^(\d{4})-…$/)`; se não casa → `return false`. Mesma divergência tri-state.

## Correção mínima exigida para audit-pass

1. Em `validateTempPassword`, após extrair `salt = plaintext.slice(0, idx)`, **decodificar mais uma camada base64** antes de comparar com a SecretKey:
   ```
   const saltBytes = Buffer.from(salt, 'base64')
   const saltAscii = saltBytes.toString('ascii')
   if (saltAscii.length === 0 || !secret.includes(saltAscii)) return false
   ```
   Conforme `TokenUtils.cs:166-169` do legado.
2. Em `case 'temp-password'`, corrigir `nome: 'PROCESSA'` → `nome: 'processa'`. Conforme `AbstractBearerAuth.cs:145`.
3. (Opcional, baixa severidade) Considerar elevar o tipo de retorno para `boolean | null` se o caller futuro precisar distinguir falha de parsing de senha-expirada/inválida. Atualmente inerte porque o `/login` colapsa em `principal = null`.

Sem o item 1, o round-trip com tokens gerados pelo legado (`/api/auth/generateTemp?segundos=N` em qualquer app Processa, ou `/api/tools/passwordTemp/{h}` do ADM, ou pela skill `/gen-processa-password`) **falha sempre** — F068 não cumpre o mandato de validar offline com paridade.
