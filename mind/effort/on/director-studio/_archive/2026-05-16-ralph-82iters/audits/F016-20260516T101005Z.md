## Asserções

### FL1 — defaults de `dates` no mount → `[hoje-1d, hoje+1d]` em CSV `yyyy-MM-DD,yyyy-MM-DD` — PASS

`generic-filter-renderer.tsx:186-191`: `case "dates"` em `computeDefaults` aplica `addDays(today, -1)` e `addDays(today, +1)`, junta com `,` via `toYMD`. Equivalente ao legado `Filtros.js:188-193`.

### FL2 — required select sem valor → submit bloqueado + erro inline — PASS

`generic-filter-renderer.tsx:399-415` `validateRequired` percorre schema; para `multi-select` exige array não-vazio (line 408-409); demais tipos bloqueiam quando `v == null || v === "" || (Array.isArray(v) && v.length === 0)` (line 410). `handleSubmit:420-422`: se `Object.keys(errs).length > 0` retorna sem chamar `onSubmit`. Renderiza msg "Campo obrigatório." em `state.errors[f.prop]` (lines 458, 570, 690).

> Nota: o tipo `select` (single) também é coberto pela mesma cláusula geral (`v == null || v === ""`). Equivalente observável ao gate de `length>0` do legado.

### FL3 — `bool` e `checkbox` ignoram required — PASS

`generic-filter-renderer.tsx:405`: `if (t === "bool" || t === "checkbox") continue` dentro de `validateRequired`. Submit prossegue mesmo com `null`/`false`. Equivalente ao gate `Filtros.js:110-115`.

### FL4 — `datetime-interval` expande `<prop>De`/`<prop>Ate` no payload — PASS

`generic-filter-renderer.tsx:346-350` em `handleFieldChange`: split por `,`, escreve `prop`, `propDe`, `propAte` (3 chaves). Reforçado em `computeDefaults:200-201` para o mount. Equivalente ao ramo `datetime-interval` em `Filtros.js:58-61`.

### FL5 — select com value `''` vira `null` no payload — PASS

`generic-filter-renderer.tsx:341-343`: `if ((t === "select" || t === "multi-select") && (raw === "" || raw == null)) value = null`. Equivalente ao ramo de `Filtros.js:56-58` (e cobre também o caso `null` que o legado não cobre — melhoria silenciosa, não regride).

### FL6 — linkedFilters cascade: dependente disabled antes de pai escolher + refetch ao mudar pai — PASS

Refetch + zero do dependente: `generic-filter-renderer.tsx:361-393` (loop sobre `field.linkedFilters`; modo "valor fixo" em 367-370; refetch via callback em 372-391; zera `lf.prop=null` em 376; gerencia `loadingFor`).

Disabled antes de pai escolher: `renderField:463-471` — calcula `linkedDependent` se algum pai do schema ainda tem valor vazio; `fieldDisabled = f.disabled || linkedDependent` (line 471) e placeholder específico no select dependente (line 632 "Selecione o filtro anterior primeiro"). Cobre a expectativa do contrato.

### FL7 — `required:true` sobrescreve `hide:true` (campo obrigatório sempre visível) — PASS

`generic-filter-renderer.tsx:146-150` `isVisible`: `if (f.required) return true` antes de checar `!f.hidden`. Equivalente a `Filtros.js:176-182`.

### FL8 — Clear parcial (texto persiste) — PASS-WITH-NOTE (divergência consciente)

`generic-filter-renderer.tsx:268-272` `resetFull` zera tudo (`setValues({})`). Default `clearMode = "full"` (line 315). Divergência consciente do legado (FL8 do contrato descreve o legado preservando texto livre — provável bug histórico). Designer endossou no [[ui-system/generic-filter]] como "corrige FL8"; smith honrou com `clearMode='defaults'` opt-in (line 273-277 `resetDefaults` recompõe via `computeDefaults`) para quem quiser paridade.

### FL9 — `onSubmit` recebe clone raso `{..._filter}` (não a ref interna) — PASS

`generic-filter-renderer.tsx:423`: `onSubmit?.({ ...state.values })`. Equivalente a `Filtros.js:72`.

### FL10 — Mount com `filter={x:'init'}` + defaults dos tipos especiais → merge — PASS

`generic-filter-renderer.tsx:177-220` `computeDefaults` inicia com `{ ...initialValue }` (line 177); pula chaves que `initialValue` já preencheu (line 180); adiciona defaults só nas demais. Para o caso da asserção (`x:'init'` não está no schema, `data` é `type:'dates'`), o resultado é `{x:'init', data:'<hoje-1d>,<hoje+1d>'}` — equivalente observável ao legado `setFilter({ ..._filter, ...newFilter })` para este input específico.

> Nota técnica (não-veto): a ordem de merge inverte vs. legado. Para chaves do schema cobertas por `computeDefaults` que **já vêm preenchidas** no `initialValue`, o Studio mantém o valor do initialValue (legado sobrescrevia com default). FL10 do contrato não cobre esse caso de colisão; mantém-se passável pela asserção literal. Vale registrar se algum caso real depender da inversão.

### FL11 — `visible={false}` → painel colapsado mas presente no DOM — VETO

**Contrato (`filtros-componente.md:219`)**: wrapper renderiza `<div className="collapse">` **sem `show`** → painel colapsado (**não removido do DOM**). Permite que o consumidor manipule `.classList.add('show')` direto via `_ref` (Bootstrap collapse).

**Studio (`generic-filter-renderer.tsx:898, 945`)**: `{desktopOpen && <form ...>}` — quando `desktopOpen=false`, o conteúdo é **desmontado** (não fica no DOM). State-based, não class-based.

A divergência é arquitetural (anti-pattern Bootstrap collapse vs. React state) e potencialmente intencional, mas **não está documentada** no contrato como divergência consciente (diferente de FL8). Asserção FL11 fere literalmente. Designer/curator precisam ratificar.

### FL12 — Botão "Pesquisar" recebe `id="btn-filtro-pesquisar-{id}"` quando prop `id` definida — VETO

**Contrato (`filtros-componente.md:220`)**: id HTML estável para E2E, vindo de `filtro.id` no model → propaga ao botão Pesquisar.

**Studio (`generic-filter-renderer.tsx:111-122, 791-793, 852-854`)**: `GenericFilterConfig.id?: string` está declarado no tipo (line 112) mas **nunca é lido pelo JSX**. Grep por `config.id` no arquivo retorna apenas comentários e tipos — zero uso em render. Os botões `<Button type="submit">Pesquisar</Button>` (lines 791, 852) não recebem `id` HTML.

E2E que dependa do seletor `#btn-filtro-pesquisar-{id}` quebra. Fix mínimo: `id={config.id ? \`btn-filtro-pesquisar-${config.id}\` : undefined}` nos dois branches (desktop/mobile).

### FL13 — `executeExternalAction=true + externalActionConfigs` → botão extra `btn-exec-external-action` — VETO

**Contrato (`filtros-componente.md:221`)**: bloco condicional na toolbar renderiza terceiro botão; click chama `externalActionConfigs.onClick(_filter)`. Habilita o modo `<GenericActionForm>` modal (consumidor real em produção, vide `GenericActionForm.js:7,124-141`).

**Studio**: `executeExternalAction` e `externalActionConfigs` **não existem** em `GenericFilterConfig` (lines 111-122) nem no JSX da toolbar (lines 786-795, 842-855). Consumidores que dependem desse modo (ações em lote modais) ficam sem suporte.

Smith declarou cobertura "FL1..FL8" — FL13 está fora do escopo declarado, mas é asserção catalogada e o `GenericActionForm` é consumidor real do legado.

### FL14 — `hideButtons=true` esconde botões "Pesquisar"/"Limpar" — PASS-WITH-NOTE

Funcionalmente coberto: `generic-filter-renderer.tsx:786` `const footer = !config.hideActions && ...`. Quando `hideActions=true`, o `footer` vira `false` e não renderiza os botões.

**Nota**: a prop foi **renomeada** de `hideButtons` (legado) para `hideActions` (Studio). Consumidores que passem o nome legado direto (model JSON com `filtro.hideButtons:true`) não terão efeito — fica visível. Se o engine não traduzir a chave no boundary, pode quebrar consumidores reais. Vale adapter no `model-engine.tsx` ou alias no tipo.

Sub-asserção do contrato: "Enter também não submete" (legado não tem `<form>`). Studio usa `<form onSubmit={handleSubmit}>` (lines 902, 946) → **Enter submete**. Divergência consciente positiva (a11y), documentada por designer em [[ui-system/generic-filter]].

### FL15 — `_ref` passado pelo pai → pai pode chamar `_ref.current.classList.add('show')` — VETO

**Contrato (`filtros-componente.md:223`)**: `<div ref={_ref}>` direto na raiz; consumidor (`GenericGridPage.js:34-38`) usa `filtroRef.current.classList` direto para abrir/fechar sem re-render.

**Studio**: nenhuma prop `_ref` em `GenericFilterRendererProps` (lines 124-136). Visibilidade controlada por state interno (`desktopOpen`, `mobileOpen`) + prop `initialOpen` (line 319). Consumidores legados que dependam de `filtroRef.current.classList.add('show')` quebram (sem ref para manipular).

Divergência arquitetural (ref-based DOM toggling é anti-pattern em React moderno), **mas não declarada como divergência consciente** no contrato e fere a asserção FL15 literalmente. Curator precisa ratificar (mais provável aceitar — alinhada com a substituição state-based; mas exige registrar como divergência intencional ou criar API equivalente, ex: `imperativeRef` com `{open, close, toggle}`).

## Plug no engine (fora das FLs, mas no diff)

**FL-plug (não numerada no contrato, mas verifiquei por ser parte do diff)**: `model-engine.tsx:85` adiciona `{ key: "filtro", feature: "F016", label: "Filtro" }` em `RENDERER_ORDER`, posicionado **entre `datagrid` e `genericcalendar`**. Contrato ([[filtros-componente]]:Integração com DataGrid2) diz que "filtro vive fora do nó datagrid, no mesmo nível raiz (irmão)" — a ordem da iteração do engine não impacta a semântica de irmãos, mas a ordem visual canônica do legado (`GenericPage.js:228-336`) é `genericform → grid → calendar → actionform → treeview → gridcollection`. O legado **não** intercala `filtro` entre `datagrid` e `calendar` (filtro é renderizado como header do `GenericGridPage`, acima do grid). O comentário em `model-engine.tsx:69-71` cita ordem canônica e não inclui `filtro` na lista. **Note**: posicionamento OK como aproximação (não há ordem oficial do legado para `filtro` standalone), mas a ordem efetiva no consumidor real (`GenericGridPage`) é `filtro → grid`. Vale conferir com designer/curator se o studio precisa do filtro acima do grid em layout "top".

> Não é veto — é apontamento de fidelidade fina. O atual `RENDERER_ORDER` colocaria filtro **depois** do grid quando ambos coexistem no model raiz.

## Recomendações

1. **FL12**: adicionar `id={config.id ? \`btn-filtro-pesquisar-${config.id}\` : undefined}` aos botões "Pesquisar" (desktop linha 791, mobile linha 852).
2. **FL13**: incluir `executeExternalAction` + `externalActionConfigs` no `GenericFilterConfig` e branch de toolbar — ou enfileirar como microfeature dedicada (F-action-form-filter) com aceite parcial ratificado pelo curator.
3. **FL15**: oferecer API imperativa equivalente (ex: `forwardRef` expondo `{open, close, toggle}` via `useImperativeHandle`) para consumidores que precisam de controle externo sem re-render. Documentar como divergência consciente.
4. **FL11**: documentar a divergência state-based vs. class-based no [[ui-system/generic-filter]] e marcar formalmente como divergência consciente, **ou** retornar ao padrão "conteúdo sempre montado, classe controla visibilidade" se houver dependência de animação CSS pura.
5. **FL14 rename**: aceitar `hideButtons` como alias deprecated de `hideActions` (line 118) — ou traduzir no boundary do `ModelEngine`.
6. **Plug-order**: realocar `filtro` antes de `datagrid`/`datagrid2` em `RENDERER_ORDER` se o engine for renderizar ambos como irmãos no mesmo container (paridade com `GenericGridPage` que coloca filtro acima da grid).
