# Veredito geral

PASSA com 7 divergências conscientes documentadas no header do componente e no UX spec, mais 1 escopo deferred (PS14/15). Nenhuma fere fidelidade semântica do contrato; todas elevam a UX corrigindo más-práticas legadas (min-3-chars hardcoded, sem debounce, sem cancel, backdrop confirmando multi). API objeto/array em vez de índice/CSV é mandato Studio explícito ("NUNCA CSV/índice", linha 4 do componente).

O smoke `/smoke/f019` cobre 5 cenários: single client, multi server (380ms simulado), multi confirm forçado, single async com flaky+retry, required validation. AbortSignal exercitado nos fetchers fake. Cobertura PS1..PS23 abaixo.

# PS1..PS23

## PS1 — placeholder vazio

**PARCIAL — divergência consciente.** Texto literal "Clique para selecionar." (`PowerSelect3/PowerSelect.js:98`) substituído por placeholder customizável (default `"Selecione..."`, `power-select.tsx:815`/`977`). Comportamento (render do placeholder quando `value=null` ou `value=[]`) preservado. `FormFieldSelect`: `{triggerContent}` com `<span className="text-muted-foreground">{placeholder}</span>` (linha 841). Multi: idem linha 1044. Smoke C1 passa `placeholder="Selecione uma cidade"` confirmando que prop chega. **OK — UX spec admite placeholder customizável; texto hardcoded legado é débito.**

## PS2 — click abre modal com search

**PASSA (com nota).** Abre Popover (desktop) ou Drawer (mobile). Search input renderiza com `aria-label="Buscar opções"`, placeholder default `"Buscar..."` (linha 816/978, divergente de `"Procurar..."` legado — texto cosmético). Lista renderiza completa quando `query.trim()===''` (filterClient retorna `options` sem filtro, linha 141). Smoke C1 demonstra inline. **OK.**

## PS3 — 2 chars abaixo do mínimo

**FERE (divergência consciente).** Contrato legado: min 3 chars hardcoded; abaixo disso `_filterValue=''` e lista completa (`PowerSelect3/PowerSelect.js:22-24`). Studio: `minQueryLength` default `1` (linha 813/975), 2 chars **já filtra** em client mode. Para server mode, `queryTooShort` aparece quando `length < minQueryLength` (linha 380-388). Cabeçalho do componente declara explicitamente: `"minQueryLength default 1 (legado tinha 3 hardcoded)"` (linha 15). Smoke C4 exercita `minQueryLength={2}`. **Divergência consciente, OK no UX spec.**

## PS4 — 3+ chars filtra substring case-insensitive

**PASSA.** `filterClient` (linha 137-144): `options.filter((o) => o.label.toLowerCase().includes(q))` — substring lowercase, identico ao legado (`PowerSelect3/PowerSelect.js:188`). **OK.**

## PS5 — single click commits objeto e fecha

**PASSA.** `pickSingle(opt)` → `commit(opt)` → `onChange(opt); setOpen(false)` (linhas 341-344, 831-834). `useEffect` em `props.open=false` reseta `query` e `activeIndex` (linhas 245-250). Payload é objeto único (não array). Smoke C1 confirma. **OK — semantica idêntica; payload objeto preservado.**

## PS6 — multi clicks NÃO disparam onSelect até confirm

**FERE (divergência consciente).** Contrato legado: multi não chama `onSelect` a cada click; só no backdrop close (`PowerSelect3/PowerSelect.js:74-81`). Studio default `commitMode='immediate'` desktop → `onCommitMulti(next)` a cada toggle (linha 334-335). Em `commitMode='confirm'` (mobile default ou forçado, smoke C3) o comportamento legado é replicado: toggles atualizam apenas `pendingSelected` e o commit acontece em `confirm()` (linha 1027-1030). Cabeçalho documenta: `"commitMode default 'immediate' desktop / 'confirm' mobile"` (linha 18). **Divergência consciente.**

## PS7 — backdrop click confirma multi

**FERE (divergência consciente).** Legado confirma via backdrop click (`PowerSelect3/PowerSelect.js:80-81`). Studio: em `confirm` mode o backdrop / outside-click executa `closeWithoutCommit` (linha 1018-1021, 1136) — descarta pendentes e exige Confirmar explícito (footer, linha 1155-1163). Em `immediate` mode não há nada a confirmar (já foi commitado). Cabeçalho: `"multi commit immediate/confirm (legado backdrop)"`. UX spec documenta. **OK — padrão de acessibilidade superior.**

## PS8 — toggle off remove por match de value

**PASSA.** `toggleMulti`: `effectiveSelected.filter((s) => !sameKey(s, opt, getOptionKey))` (linha 332). `sameKey` compara por `getKey` (default `option.value`, linha 125-135). Identico semanticamente. **OK.**

## PS9 — render multi com N>1: 1 chip + "..." + "+N-1"

**FERE (divergência UX).** Contrato: 1 chip único + `<span>...</span>` + `+N-1` strong (`PowerSelect3/PowerSelect.js:102-138`). Studio: `chipsVisible` configurável (default 2 desktop / 1 mobile, linhas 1002-1006); overflow `+N` em badge muted (linha 1058-1062). Sem separador "..."; "+N" não-strong. Com 3 selecionados, desktop renderiza 2 chips + `+1`; mobile 1 chip + `+2`. Smoke C2 usa `maxChipsVisible={3}`. **Divergência UX consciente (display mais informativo).**

## PS10 — label ≥20 chars trunca a 17

**PASSA (com técnica diferente).** Legado: JS `substring(0,17)+"..."` (`PowerSelect3/PowerSelect.js:116-118`). Studio: `Chip` usa `max-w-[12rem]` + `<span className="truncate">` (linha 706) + `title={label}` (linha 704) — truncate CSS com tooltip nativo. Resultado visual equivalente, mas com fallback acessível (full label no hover). **OK — substring exata não preservada, mas semantica de truncamento + sinalização visual sim.**

## PS11 — _disabled=true bypass

**PASSA.** `disabled` prop → `isInteractive = !disabled && !readOnly` (linha 829/994). Trigger `onClick={() => isInteractive && setOpen(true)}` (linha 904/1128); Popover/Drawer `onOpenChange` checa `isInteractive` (linhas 908, 925, 1134, 1169). Trigger HTML `disabled={disabled}` (linha 634). **OK.**

## PS12 — _disabled='true' string-bool

**FERE.** Legado coerce string-bool via `checkBooleanValue('true')===true` (`PowerSelect3/PowerSelect.js:67`). Studio: prop tipada `disabled?: boolean` (linha 72), sem coerce. Se consumidor passar `"true"` string TypeScript reclama; em runtime JS truthy-string entra como truthy → `isInteractive=false` → comportamento acidentalmente equivalente, mas não auditado. **Divergência de API — API limpa Studio (boolean estrito) é mandato e aceitável.** Consumidor (smith) deve coerce antes (não dentro do widget).

## PS13 — click no chip remove via onRemove(index)

**FERE (divergência consciente de API).** Legado: `onRemove(index)` recebe índice numérico (`PowerSelect3/PowerSelect.js:62, 109`). Studio: `Chip onRemove` → `removeChip(opt)` → `onChange(value.filter((o) => !sameKey(o, opt, getOptionKey)))` (linhas 1032-1035). Payload final é o array novo via `onChange`, não callback separado com índice. Cabeçalho componente proíbe explicitamente: `"API objeto/array (NUNCA CSV/índice)"` (linha 4). Chip também previne abertura do modal: `e.stopPropagation()` (linha 712) — comportamento `data-event` legado preservado por mecanismo diferente. **Divergência arquitetural consciente (API uniforme objeto/array).**

## PS14 — pipeliner=true injeta flag

**NÃO COBERTO (escopo deferred).** Studio não implementa prop `pipeliner` (não está em `CommonProps`/`FormFieldSelectProps`/`FormFieldMultiSelectProps`). Contrato registra (Inércia §Notas): `"Provavelmente não relevante para fluxo geral do Studio fora do AppBuilder (F015 deferred)"`. **OK por escopo — F015 deferred.**

## PS15 — pipeliner=false default

**N/A (mesmo que PS14).** **OK por escopo.**

## PS16 — selectOptions=undefined não quebra

**PASSA.** `options ?? []` (linhas 871, 1094) → `filterClient([], '')` retorna `[]` → `showEmpty` branch (linha 508-517) renderiza `emptyMessage` com ícone `MagnifyingGlassMinus`. Nenhuma exception. Studio supera legado ao mostrar mensagem de empty estado (legado renderia modal silencioso). **OK + ganho UX.**

## PS17 — prop value mudou para [] sincroniza interno

**PASSA.** Studio é controlled completo: `value` prop é única fonte da verdade — não há `selected` interno que possa driftar (problema apontado em §Inércia legada). `effectiveSelected = commitImmediate ? selected : pendingSelected` (linha 309-313); `selected` deriva de `value`. Em `confirm` mode, useEffect ressincroniza `pendingSelected = value` ao abrir (linha 1012-1016). **OK — controlled-only elimina drift do legado por design.**

## PS18 — V1 POST /proc/ body=formState

**PASSA por substituição semântica.** Studio não faz HTTP — abstrai via prop `fetchOptions: (query, signal) => Promise<Option[]>` (linha 79-82). Consumidor compõe a chamada (`postAsync('/proc/...', getFormState())` no caso, mapeando para `useSelectFields` futuro). Padrão `useSelectFields` documentado em sub-contrato `select-options-endpoint.md` (a criar). Smoke C2 (`fakeFetchEmpresas`) exemplifica integração. **OK — cobertura semântica do contrato HTTP delegada ao consumidor.**

**PASSA por substituição semântica.** Mesma análise PS18: consumer concerno. **OK.**

## PS20 — V1 GET /select/lojas cru

**PASSA por substituição semântica.** Idem. **OK.**

## PS21 — options.length>0 não dispara HTTP

**PASSA.** `resolveMode` (linhas 782-792): se `searchMode='auto'` e `fetchOptions` ausente → `'client'`; se `searchMode='client'` explícito → cliente. `options` inline + sem `fetchOptions` = sem HTTP, comportamento legado preservado. Precedência `options>fetchOptions` documentada em contrato §Notas implementação: `"options ganha"` — para Studio o consumidor escolhe explicitamente passando uma ou outra (Studio não mistura num único call, simplificação consciente). **OK.**

## PS22 — allowUpdateSelectOptions=false não re-fetch

**FERE PARCIALMENTE (divergência consciente).** Legado: V1 não re-fetch após primeira carga exceto se flag true (`PowerSelect.js:111-112`). Studio: client mode nunca re-fetch (options são fixas vindas da prop). Server mode tem memo TTL 5s (linhas 146-151, 263-269) — re-fetch a cada query nova fora do TTL. Não há flag "freeze". Cache shift: legado dependia de "carrega uma vez no mount"; Studio depende de memo curto + responsabilidade do consumidor para cache longo. Cabeçalho não menciona explicitamente, mas memo TTL é tradeoff visível no código. **Divergência arquitetural: cache responsability moved to memo+consumer.** UX spec deveria documentar — apontar pra Curator.

## PS23 — useSelectFields fixedList shortcut

**PASSA.** `selectDataType:'fixedList'` no legado curto-circuita HTTP usando `options` inline. Studio equivalente: passar `options=[...]` sem `fetchOptions` (`resolveMode → 'client'`). Smoke C1, C3 e C5 exercitam esse caminho. **OK.**

# Pontos a revisitar fora desta auditoria

- **PS14/15** (pipeliner): retomar quando F015 (AppBuilder) sair do deferred. Hoje quem precisar da flag pode passar via spread em option e ler downstream — mas perde-se o canal "marca origem na seleção".
- **PS22 cache**: confirmar com Curator se memo 5s TTL é suficiente para casos de form com muitas instâncias do mesmo select; legado tinha cache global por var-de-módulo no `<Filtros>` (race-condition-prone, vide [[filtros-componente]]). Studio não replica esse cache global — provavelmente correto, mas merece nota explícita no UX spec.
- **`name`/`state`** props legadas inúteis (contrato §Inércia): Studio corretamente omitiu. Sem aviso ao consumidor — quem migrar Filtros precisa parar de passá-las.
- Texto literal `"Buscar..."` vs `"Procurar..."` (PS2): cosmético; UX spec já admite. Considerar i18n no futuro.
