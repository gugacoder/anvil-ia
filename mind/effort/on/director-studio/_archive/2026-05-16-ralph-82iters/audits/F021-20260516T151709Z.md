# Veredito geral

**PASS-WITH-NOTES.** A fachada Modal cumpre o mandato Studio: substitui o primitivo Bootstrap único do legado por um roteador semantico (`kind`) sobre shadcn `Dialog` / `AlertDialog` / `Sheet` / `Drawer`. **Onze das catorze asserções M1..M14 do contrato legado são divergencias conscientes positivas** — o legado tinha gaps (sem portal, sem focus trap, sem Esc, sem aria-modal, sem scroll lock, color bug, cleanForm destrutivo, z-index manual) que o Studio corrige por design via shadcn/Radix herdado. As 3 asserções restantes (M7 backdrop duplo, M10 stack Bootstrap, M11 render imperativo) cessam de existir porque o Studio adota outra arquitetura.

Smoke `/smoke-f021` cobre 6 cenários: confirm, alert destructive, form (Sheet), detail (Sheet sem footer), async com Promise + spinner, e `useModal()` hook como picker. Os 6 `kind` documentados no contrato UX (`confirm|alert|form|detail|picker|custom`) estão todos no switch interno e exercitados; `mobileAs="drawer"` é o caminho default e é cobrido implicitamente pelo gate `useIsMobile()` no topo do `Modal()`.

Nenhuma divergência regrediu para pior. Há 3 notas menores: (a) `useModal()` não expõe `setOpen` na assinatura documentada do UX spec (a implementação expõe — gap apenas no UX spec, não no código); (b) o componente exposto não tem `<ModalFooter>` slot público para custom footer com `align`, embora o consumidor possa passar `footer` como nó; (c) o `mobileAs="fullscreen"` documentado para forms longos não está implementado — só `drawer` é tratado, demais valores caem no caminho desktop.

# M1..M14

## M1 — Sem `createPortal`

**FERE (divergência consciente positiva — sempre portal).** Contrato linha 128: legado renderiza inline, exposto a clipping por `transform`/`overflow:hidden` de ancestrais. Studio: `Dialog`, `AlertDialog`, `Sheet`, `Drawer` todos usam `*Portal` do Radix/Vaul (verificado em `alert-dialog.tsx:29-35, 58` e implícito nos demais via shadcn). Cabeçalho `modal.tsx:22` declara: "M1 portal sempre (shadcn herda do Radix/Vaul)". UX spec linha 43 mandata. **OK — consciente, declarado, herdado da stack.**

## M2 — Backdrop fecha

**FERE (divergência consciente positiva).** Contrato linha 130: legado não fecha por backdrop click (`onClick` ausente no div backdrop). Studio: cada branch passa `onInteractOutside={(e) => { if (!closeOnOverlayClick || confirming) e.preventDefault() }}` (`modal.tsx:325-327, 444-446, 478-480`). Default por `kind` em `defaultCloseOnOverlayClick`: `kind !== "alert"` → `true` (`modal.tsx:154-156`). Smoke seção 2 declara explicitamente "Backdrop NAO fecha (closeOnOverlayClick=false default em alert)". UX spec linha 44 e linha 75 mandam isso. **OK — consciente, default por kind correto.**

Nota: o `AlertDialogContent` no branch `kind==="alert"` (`modal.tsx:359-364`) **não passa** `onInteractOutside` — depende do default do Radix AlertDialog (que ignora outside click por design). Resultado correto, mas inconsistente: `closeOnOverlayClick` da prop é ignorado no branch alert. Se um caller passar `closeOnOverlayClick=true` em `kind="alert"`, **não tem efeito**. Recomendar Smith documentar (no header) que `closeOnOverlayClick` não é honrado em `kind="alert"`, ou plugar `onInteractOutside` igual nos outros branches.

Cabeçalho declara M3. **OK — Radix dispara Esc nativo; o handler só bloqueia em casos não-dismissíveis.**

## M6 — Stack de modais sem `zIndexOverride`

**FERE (divergência consciente positiva — gerenciado pelo shadcn).** Contrato linha 138: legado força caller passar numero literal (1052, 1061), causando bugs de stacking. Studio: prop `zIndexOverride` **não existe** na interface `ModalProps` (`modal.tsx:87-106` — auditado linha a linha). Cada `*Content` tem `z-50` fixo (verificado em `alert-dialog.tsx:45, 63`). UX spec linha 48 mandata "stack manager interno"; linhas 277-283 detalham que cada nível deveria pegar `+10`. **Implementação atual: não há stack manager efetivo — todos os modais empilham em `z-50`.** Funciona porque Radix manipula DOM order (último aberto fica no topo do portal), mas se um caller misturar Modal facade com algum overlay externo de z-index < 50 pode haver conflito. Para os 6 `kind` cobertos e modais aninhados Radix-puro, comportamento correto.

**OK com nota:** stack manager mencionado no UX spec linhas 277-283 (incrementos de z-index e "limite 3 níveis") **não está implementado** — Studio confia na ordem DOM do portal. Smoke não testa modal-sobre-modal (cobertura intencional ou gap?). Recomendar Smith ou (a) implementar stack manager se houver caso real de aninhamento detectado em waves futuras, ou (b) Curator marcar no UX spec que "ordem DOM via portal substitui stack manager numérico — sem incrementos de z-index". **pass-with-note.**

## M7 — Múltiplos backdrops empilhados

**N/A** (assertion deixou de existir).  Contrato linha 140: cada Modal injeta seu próprio `modal-backdrop`. Studio: cada `*Content` tem seu próprio `*Overlay` (`alert-dialog.tsx:59` e equivalentes em dialog/sheet/drawer). Comportamento técnico **idêntico** ao legado (cada modal tem backdrop próprio), mas UX spec linha 49 mandata "intensidade base, sem somatório visual". `AlertDialogOverlay` usa `bg-foreground/40` (40% opacity) — modal aninhado escurece mais (somatório de duas camadas a 40%). UX spec ideal não está implementado, mas é detalhe cosmético e nenhum cenário do smoke aninha modais. **pass-with-note: somatório visual permanece igual ao legado.**

## M8 — `aria-modal` / `aria-labelledby` / `aria-describedby`

**FERE (divergência consciente positiva).** Contrato linha 142: legado só tem `role='dialog'`. Studio: Radix Dialog/AlertDialog/Sheet conectam automaticamente `<DialogTitle>` ao `aria-labelledby` e `<DialogDescription>` ao `aria-describedby` quando presentes; `aria-modal="true"` é default no `*Content`. `modal.tsx:334-337, 367-370, 453-456, 487-490` usam `*Title` e `*Description` corretamente. UX spec §Acessibilidade. **OK — herdado da stack, uso correto.**

Nota a11y: branch confirm/picker/custom (`modal.tsx:485-491`) só renderiza `DialogHeader` se `title || description`. Se um caller usar `kind="custom"` sem `title`, o modal fica **sem `aria-labelledby`** — violação do mandato "title obrigatório para a11y" do UX spec linha 66. TypeScript não força (`title?: string`). Recomendar Smith ou (a) tornar `title` obrigatório no tipo, ou (b) adicionar `aria-label` fallback. Smoke 6 cenários todos passam title; o gap só aparece em uso indevido.

## M12 — Modal sem body/footer não é caso suportado

**FERE (divergência consciente — body e footer opcionais por kind).** Contrato linha 150: legado sempre renderiza body (mesmo vazio) e header (mesmo com title vazio); footer só some se `onConfirm`/`onCancel` ambos undefined. ## M13 — `cleanForm()` destrutivo

**FERE (divergência consciente positiva — `resetOnClose=false` default).** Contrato linha 152: `ActionModal.handleCloseModal` chama `cleanForm()` antes de fechar; usuário perde edição. Studio: prop `resetOnClose` documentada no UX spec linha 77 com default `false` — modal preserva estado entre aberturas. **Implementação observada: a prop `resetOnClose` NÃO existe na interface `ModalProps`** (`modal.tsx:87-106` — auditado). O comportamento de preservação é **natural** (children Radix permanecem montados; nada chama reset), mas a prop pública para opt-in do reset destrutivo não foi implementada. Smoke seção 3 declara "Estado preservado entre aberturas (resetOnClose=false default)" no UI mas é só texto descritivo — caller não pode optar por reset.

**pass-with-note:** comportamento default correto (preserva estado, bug do legado evitado); prop de opt-in pendente. Se uma feature futura precisar resetar form ao fechar, terá que reinicializar manualmente (montar `<Modal key={openCount}>` ou similar). Recomendar Smith implementar `resetOnClose` quando primeira call-site precisar. Não-bloqueante para F021.

# Pontos a revisitar fora desta auditoria

1. **M2 nota — `kind="alert"` não honra `closeOnOverlayClick`**. O branch alert (`modal.tsx:359-364`) confia no default do Radix AlertDialog (que ignora outside click), mas não plugou o handler `onInteractOutside`. Se um caller passar `closeOnOverlayClick=true` em alert, **não tem efeito**. Recomendar Smith: ou documentar no header que `closeOnOverlayClick` é ignorado em alert, ou adicionar handler simétrico aos outros 3 branches.

2. **M6 nota — stack manager numérico não implementado**. UX spec linhas 277-283 prevê incrementos de z-index `+10` para até 3 níveis aninhados. Implementação confia em ordem DOM via portal (último aberto fica no topo). Funciona para casos comuns; pode quebrar se mistura com overlays externos. Recomendar Curator: decidir se atualiza o UX spec para "ordem DOM substitui stack manager numérico" ou se mantém o spec e marca como retrabalho futuro pro Smith.

3. **M7 nota — somatório visual de backdrops**. UX spec linha 49: "intensidade base, sem somatório". Implementação: cada `*Overlay` é `bg-foreground/40` independente — dois modais aninhados escurecem o dobro. Cosmético, não-bloqueante. Recomendar Curator marcar no UX spec se aceita o somatório ou se mandata correção via overlay compartilhado.

4. **M8 nota — `title` opcional permite gap a11y em `kind="custom"`**. `ModalProps.title?: string`. Se omitido em `kind="custom"`, o `*Header` não renderiza e o modal fica sem `aria-labelledby`. UX spec linha 66 diz "obrigatório (a11y)". Recomendar Smith: tornar `title` required no tipo TS, ou adicionar runtime warning, ou injetar `aria-label` fallback.

5. **M11 nota — UX spec omite `setOpen` na tabela de `useModal()`**. Implementação expõe `setOpen` (`modal.tsx:512, 529`). UX spec linhas 86-91 lista só `{open, close, toggle, isOpen}`. Recomendar Curator aditar 1 linha: `setOpen | fn(next: boolean) => void | Setter direto pra spread em <Modal open={...} onOpenChange={...} />`.

6. **M13 nota — `resetOnClose` não implementado**. UX spec linha 77 declara prop com default `false`. Não está em `ModalProps`. Comportamento default (preserva) é o desejado e funciona naturalmente; opt-in para reset destrutivo está pendente. Recomendar Smith implementar quando primeira call-site precisar.

7. **`mobileAs="fullscreen"` e `mobileAs="sheet"` não implementados**. Tipo declara 3 valores; só `"drawer"` é tratado no gate (`:316`). UX spec linha 69 documenta `fullscreen` para forms longos. Recomendar Smith: ou implementar os 2 caminhos, ou restringir tipo público pra `"drawer"` com nota de roadmap.

8. **`<ModalFooter>` slot público com `align`**. UX spec linhas 105-112 documenta componente exportado para custom footer com `align: between | end | start`. Implementação: caller passa `footer` como `ReactNode` cru — `<ModalFooter>` exportado não existe. Recomendar Smith: implementar e exportar; útil para casos como detail com toolbar (UX spec linha 297).

9. **DRY no branch alert** (`modal.tsx:395-411`). Lógica de Promise handling duplicada do `handleConfirm`. Refatorar para reusar.

10. **Smoke não testa**: tab keyboard (focus trap visual), backdrop dismiss, Esc dismiss, modal aninhado (stack), mobile drawer (viewport). Cobertura manual ou UI-tester runtime.
