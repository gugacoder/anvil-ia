- **Auth-scheme legado mapeado** via `AppClientService.BuildHeader` (PortalDirector.Services/AppClientService.cs:43-56): switch por `DFchave`. `case "cotacao"` → `Basic base64("processa|{DFdominio}:99")`. `default` → `Bearer <JWT>` com `DirectorIdentity` **fixa** (`Id=1, Name="processa", CodEmpresa=0, NomeEmpresa="Processa") { Domain = DFdominio }` — **não propaga identity do usuário corrente**. Header HTTP extra `Domain: {DFdominio}` em **todas** as chamadas. URL final `{DFendereco}/api/proc/{proc}` literal (não normaliza trailing slash; preserva path-suffix como `checkin/`).
- `DFchave` é o **discriminador estável cross-tenant** — `DFid_aplicacao` varia per-tenant (cotacao=4/5/6/7/8/11 dependendo da base — Imperial=5, Bazinho=11, Castro=7, PCP=8, Vicosense=4, Bergao=6).
- `DFhabilitado=0` **NÃO bloqueia** chamadas via proxy multi-app — só esconde do menu home (`acesso.obter_aplicacoes_pagina_home` filtra `WHERE DFhabilitado=1 AND DFchave NOT IN ('portal-aws')`).
- Data-quality bug observado: `processa-sped` tem `DFporta=5003` mas `DFendereco='http://localhost:5005'` em todos os tenants — seed inconsistente, sem efeito em runtime porque clients ignoram `DFporta` (R17).
- 5 caminhos de resolução documentados no contrato: (1) `PortalAwsClient` bridge dedicado para `portal-aws` (lê 2 colunas, usa identity do usuário corrente, JWT inter-tenant); (2) `AppClientService.ExecProc/GetProc` resolver genérico (modelo de F110, switch auth por chave, identity de serviço fixa); (3) `CotacaoIntegradorClient` Basic estática hardcoded para `cotacao-integrador` (não usa `DFdominio`); (4) `EdocController` para `edoc`; (5) `acesso.obter_aplicacoes_pagina_home` projeção para menu home com filtros.
