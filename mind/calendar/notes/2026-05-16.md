# 2026-05-16 — notas do dia

- Escavação F019 — `PowerSelect3` (typeahead+async). Descoberta crítica: F019 está **mal-rotulada no manifest**. O componente que vive em `react-tools/components/PowerSelect3/` **não é typeahead async** — é um modal client-side de filtro local sobre `selectOptions[]` injetado pelo pai. O typeahead/async real está em `react-tools/components/PowerSelect.js` (V1, ainda na public API como `PowerSelect`) e o `useSelectFields` hook (carga via `/proc/`, `/select/`, `/selectquery/`). Coexistência de 3 versões: V1 (`PowerSelect.js`, async + react-select), V2 (`PowerSelect2.js`, react-select sem fetch), V3 (`PowerSelect3/PowerSelect.js`, modal próprio + filtro client). Contrato cobre as 3 + endpoint convention via `useSelectFields`.
- Notas de auditoria: nenhum dos 3 implementa debounce, mínimo de chars, cancel de requisição, cache (selectOptions cache é responsabilidade do **consumidor**, não do PowerSelect — Filtros.js mantém var-de-módulo `selectOptions` global; Form/Dashboard mantêm prop). Typeahead "remoto" como expectativa do manifest **não existe no legado** — toda filtragem por digitação é client-side sobre lista já carregada.
- Sub-contrato candidato: `select-options-endpoint.md` (regra `useSelectFields.sendRequest` — `/proc/*` POST com state, `/selectquery/{key}?parametro_id=` GET, `{api}` GET cru, `selectDataType:fixedList` curto-circuito). Já era candidato apontado por F016; F019 reforça.
- Manifest atualizado: F019 muda `Contract` para [[power-select]] e ganha nota de re-rotulagem (rótulo legado "typeahead+async" é ilusório).
